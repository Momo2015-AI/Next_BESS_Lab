### 1.4 直流功能容量公式
```
DC Functional Capacity = DC Installed x (1 - delta%) x SOH(i)
```
其中 delta% 为可用容量损失百分比, SOH(i) 为第 i 年健康状态

### 1.5 效率链分解 (12+ 因子)
电芯效率 -> DC/DC 变流器 -> 直流电缆 -> PCS -> LV/MV 变压器 -> MV 电缆 -> HV 变压器 -> 交流辅助功耗 -> 自放电 -> 均衡损耗 -> 冷却功耗 -> 控制系统功耗

## 5. 最终评估

### 5.1 能否支持端到端开发?

**结论: soh-sim 当前状态可为核心投标计算提供基础支持, 但需要经过第一阶段 (核心算法对齐) 和第二阶段 (投标工具集) 改造后方能输出符合 RFP 要求的完整投标文件。**

具体来说:

| 维度 | 当前可支持程度 | 改造后可支持程度 |
|------|------|------|
| SOH 退化预测 | 60% (公式框架正确, 但测试条件/标准不匹配) | 95% |
| 能量核算 | 50% (公式简化, 不含 RFP delta% 参数) | 90% |
| 财务分析 | 80% (方法齐全, 需适配 DEWA 税务结构) | 90% |
| BOQ 管理 | 70% (结构正确, 需 RFP 格式映射) | 85% |
| 投标文件生成 | 5% (无模板) | 80% |
| 认证合规 | 0% (无此模块) | 85% |
| LTSA/O&M | 0% (无此模块) | 75% |
| 电网/热/消防仿真 | 0% (需外部工具) | 0% |

### 5.2 soh-sim 的独特优势

1. **架构可扩展**: 模块化的 Python 后端 + Vue 前端, 新增算法和页面成本低
2. **财务引擎成熟**: 5 种收入模型、完整债务/折旧/税务建模, 已接近 RFP 要求
3. **多语言支持**: 中文/英文/阿拉伯文, 对 Masdar (阿联酋) 投标有天然优势
4. **Phase 工作流**: 已有 Phase1-5 分阶段流程, 可映射到 RFP Phase A/B/C
5. **增容引擎**: 已支持 26 年增容规划和各资产年龄追踪, 可扩展为三阶段部署

### 5.3 建议策略

1. **立即启动第一阶段**: 核心算法对齐是投标的基础, 无此则所有计算不可信
2. **第二阶段与投标准备并行**: 在算法改造期间, 可用手工 Excel 过度投标表格生成
3. **第三/四阶段按需推进**: LTSA 和设计文件在商务谈判阶段更关键, 不急于投标截止前完成
4. **建立外部工具接口**: 对于电网/热/消防仿真, 搭建数据导出接口供专业团队使用, 不在 soh-sim 内部实现

### 5.4 工作量总计

| 阶段 | 估计工作量 | 累计 |
|------|------|------|
| 第一阶段 (核心算法) | 19 人天 | 19 人天 |
| 第二阶段 (投标工具) | 32 人天 | 51 人天 |
| 第三阶段 (LTSA/O&M) | 15 人天 | 66 人天 |
| 第四阶段 (设计文件) | 16 人天 | 82 人天 |
| **总计** | **82 人天** | - |

上述估计基于单个全栈开发人员, 不含外部电网/热/消防仿真工具的使用时间。

### 7.2 流程问题诊断

**问题 1：缺少哪些阶段？**

缺失以下 4 个关键阶段：
1. **资格预审阶段** (Qualification Gate) —— 投标的前置门槛，无此阶段系统无法判定一个项目是否值得投入资源
2. **投标决策阶段** (Bid/No-Bid Decision) —— RFP 需求解析、参数 diff、偏离评估、Go/No-Go 商业决策流程
3. **澄清与谈判阶段** (Clarification & Negotiation) —— 3 轮 RFQ 多轮澄清迭代，方案和报价需支持版本对比和增量更新
4. **合同签署后交付阶段** (Post-Award Execution) —— FAT/SAT/PCOD 里程碑追踪、制造进度、O&M 交接

**问题 2：现有阶段顺序是否合理？**

当前顺序 Phase1→Phase2→Phase3→Phase4→Phase5 在逻辑上基本合理，但存在以下问题：

- **Phase1 (场地调研) 应该在资格预审之后**：真实项目中，必须先判定"这个项目我们有资格投"才投入资源做详细场地调研。当前设计假设用户已获得投标资格。
- **Phase2 (设备选型) 应在 Phase3 (性能仿真) 的更早阶段深度绑定**：真实项目中，设备选型（电芯型号 → GB/T 36276 退化曲线 → SOH 预测）与性能仿真是循环迭代关系。当前 Phase2 独立设计，与 Phase3 的耦合通过手动传参实现。
- **Phase4 (财务) 应在 Phase3 (性能仿真) 完成后才能准确计算**：当前顺序正确，但 Phase4 缺少对 Phase A/B/C 的分阶段独立财务处理。

**问题 3：哪些现有阶段需拆分细化？**

- **Phase2 需拆分为**：2A 效率链建模、2B 热管理方案选择、2C PCS 并网方案、2D 消防方案选型、2E 设备型号确定(电芯/电池包 二选一)、2F 直流/交流侧详细设计
- **Phase3 需拆分为**：3A GB/T 36276 标准退化验证、3B 沙漠加速因子叠加、3C 能量核算(按 RFP 公式)、3D 可用率(MTBF/MTTR)计算、3E RTE 逐因子验证
- **Phase5 需拆分为**：5A BF#1-8 投标表格生成、5B 偏离表自动编制、5C 技术报告 Word/PDF 渲染、5D 单线图 SVG 导出

**问题 4：是否存在循环反馈？**

是的，RFP 要求多轮澄清(3 轮 RFQ)，但 soh-sim 当前设计是**线性单次流程**，不支持以下循环：

- **方案迭代**：澄清过程中技术方案参数变更 → 需重新跑 Phase3 仿真 → 重新计算 Phase4 财务 → 重新生成 Phase5 报告。当前系统不支持"版本快照 + diff 对比"。
- **价格迭代**：多轮报价中 CAPEX 和 LTSA 价格调整 → 需重新计算财务指标。当前系统不支持"标前/标后/最终"多版本 BOQ 管理（只有 Main/Alternative 两个版本，不够）。
- **偏离项动态更新**：技术偏离表随澄清答复动态变化。当前系统无偏离管理模块。

建议新增：
- **项目版本管理**：每个项目支持多个 Scenario，每个 Scenario 对应一轮澄清后的完整技术-财务方案快照
- **Diff 视图**：Scenario A vs Scenario B 的技术参数差异、财务指标差异对比
- **变更追踪**：参数变更日志(谁/何时/从什么改成了什么/原因)

**问题 5：多阶段并行(Phase A/B/C 同时进行但进度不同)能否处理？**

**当前系统不能处理。** 原因如下：

- 现有 `augQty[]` 一维数组仅仅表达了"每年新增多少台"，无法表达：
  - 不同 Phase 的设备型号不同(Phase B 可能使用新型号电芯)
  - 不同 Phase 的折旧起点不同(Phase A: Y1, Phase B: Y3, Phase C: Y5)
  - 不同 Phase 的 CAPEX 单价不同(分阶段签合同，价格不同)
  - 不同 Phase 的 O&M 合同独立(每个 Phase 独立 LTSA)
  - 不同 Phase 的投运进度不同(Phase C 还在制造时 Phase A 已在运行)

需要全新设计：
```python
phases = {
    "phaseA": {"installYear": 1, "capacity": 260, "capexProfile": {...}, "opexProfile": {...}},
```

## 8. 技术+财务视角重聚焦（排除资质/认证/业绩类）

用户关注领域：技术方案设计 + 财务建模。排除：投标资格(BNEF/业绩)、认证合规矩阵(60+标准)、生产资质声明。

经筛选后，**技术与财务视角下共有 24 项功能缺口，其中 7 项 P0**：

### 技术+财务视角 P0 清单（7 项）

| 编号 | 缺失功能 | 说明 |
|------|----------|------|
| T-01 | 12 因子效率链分解模型 | 当前 `acEfficiency` 单一乘数无法区分电芯/DC-DC/电缆/PCS/变压器各级损耗 |
| T-02 | DC Functional Capacity 精确公式 | RFP 公式 `DC_Installed×(1-Δ%)×SOH(i)` vs 当前 `ratedEnergy×qty×DoD×RTE×SoH×AC_eff` |
| T-03 | GB/T 36276 标准退化曲线 | 4 条标准测试曲线(0.125P@25°C/45°C, 0.25P@25°C/45°C) + 实际工况插值 |
| T-04 | 沙漠环境加速退化因子 | 55°C Arrhenius 修正 + 沙尘腐蚀 + 100%RH 湿度加速，当前模型无环境因子 |
| T-05 | 三阶段(Phase A/B/C)独立财务建模 | Phase A(Y1-Y3)/B(Y3-Y5)/C(Y5-Y7) 独立 CAPEX/OPEX/现金流/IRR，当前仅一维 augQty[] |
| T-06 | 参数 diff 引擎 + 偏离表(BF#8) | RFP 技术条款结构化 → 与系统配置自动比对 → "满足/替代/偏离"三态矩阵 |
| T-07 | 技术参数表(BF#1) + 性能参数表(BF#2) 自动生成 | 从系统配置/仿真结果自动填充到 RFP 格式表格 |

### 流程重聚焦（技术+财务视角）

去掉资质审查和认证后，流程核心链路为：

```
Phase 1 — 方案设计
  └─ 场地环境 → DC功能容量(RFP公式) → 12因子效率链 → 设备选型

Phase 2 — 技术分析
  └─ GB/T 36276 退化验证 → 沙漠因子叠加 → 能量核算(A/B/C独立) → 可用率计算
  └─ 偏离分析(参数diff) → BF#1/2/3/8 技术表格生成

Phase 3 — 财务建模
  └─ BOQ → CAPEX(分Phase) → LTSA成本 → 多收入模型 → 独立+合并IRR/NPV
  └─ BF#6/7 商务表格生成

Phase 4 — 澄清迭代
  └─ 版本快照管理 → Scenario diff对比 → 方案优化循环

Phase 5 — 输出交付
  └─ 技术报告Word/PDF → 单线图 → 甘特图
```

### 核心结论

从纯技术与财务视角看，soh-sim 的退化引擎和财务引擎架构正确、基础扎实，但**公式精度不足**（效率链、DC 公式、退化曲线）和**输出格式不匹配**（BF 表格、偏离表）是主要障碍。补齐 7 项 P0 功能后，系统即可支撑 DEWA VII 级别项目**在技术方案设计和财务报价编制环节**的端到端计算需求。资质/认证/业绩等商务边界条件可通过人工 Excel 弥补，不需在系统内实现。
